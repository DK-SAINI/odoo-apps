Features

Everything you need for secure AI-ERP integration

🔒

REST API + XML-RPC

Full REST API with JSON responses plus XML-RPC proxy for legacy tools. Both protected by MCP permission layer.

✅

Per-Model Access Control

Expose only the models you need with granular CRUD permissions and field-level restrictions per model.

🔑

Bearer Token + Basic Auth

Authenticate via API Key (Bearer Token) or HTTP Basic Auth. Supports Odoo's native API key system.

⏱

Rate Limiting

Configurable per-minute rate limits to prevent API abuse. Returns retry-after headers when exceeded.

📋

Full Audit Logging

Every API call logged with user, IP, model, operation, status, and duration. Auto-cleanup of old logs.

🌐

IP Whitelist & Caching

Restrict access by IP address. Built-in response cache with configurable TTL for read-heavy workloads.

Setup Guide

Configure MCP Server in 5 easy steps

1

Install & Enable MCP Server

After installing the module, go to Settings and click MCP Server in the left sidebar. Toggle the switch to enable MCP Server. You can also configure rate limits, IP whitelist, caching, and audit logging here.

Settings > MCP Server
2

Add Models to Expose

Navigate to the MCP Model Access list. Here you can see all currently exposed models with their permissions. Click New to add a model.

Settings > Technical > MCP Server > Model Access
3

Configure Model Permissions

In the model form, select the Odoo model to expose (e.g., Contact / res.partner). Toggle the CRUD permissions: Read, Write, Create, Delete. You can also set:

• Allowed Fields — JSON list of fields to expose (empty = all fields)
• Cache TTL — Cache duration in seconds for read operations
• Allowed Groups — Restrict access to specific user groups
• Notes — Description for documentation purposes

MCP Model Access > New (or click existing record)
4

Generate API Key

Go to your user profile and navigate to the API Keys tab. Click New API Key, give it a description, and set the scope to rpc. Copy the generated key — you'll need it to configure your AI client.

Settings > Users & Companies > Users > [Your User] > API Keys tab
Tip: Generate a unique API key for each AI integration. This makes it easy to revoke access for a specific tool without affecting others.
5

Monitor with Audit Logs

Every MCP API call is automatically logged. View logs in list format or switch to graph/pivot view for analytics. Logs capture user, IP, model, operation, status (success/error/denied), and response time.

Settings > Technical > MCP Server > Audit Logs
📈

Audit Analytics (Graph/Pivot View)

Switch to the graph or pivot view to analyze API usage patterns — see which models are most accessed, error rates, and performance metrics over time.

API Endpoints

Complete REST API reference

Public Endpoints (No Auth Required)

MethodEndpointDescription
GET /mcp/api/v1/health Health check — returns MCP status, version, timestamp

Authenticated Endpoints (Bearer Token or Basic Auth)

MethodEndpointDescription
GET /mcp/api/v1/system/info System info — Odoo version, database, exposed model count
POST /mcp/api/v1/auth/validate Validate credentials, return user info and MCP roles
GET /mcp/api/v1/models List all exposed models with CRUD permissions
GET /mcp/api/v1/models/<model>/fields Get field metadata (name, type, required, readonly, etc.)
POST /mcp/api/v1/models/<model>/search Search records with domain filter, fields, limit
POST /mcp/api/v1/models/<model>/read Read specific records by IDs
POST /mcp/api/v1/models/<model>/browse Paginated browse with offset, limit, has_more
POST /mcp/api/v1/models/<model>/count Count records matching a domain filter
POST /mcp/api/v1/models/<model>/create Create a new record with field values
POST /mcp/api/v1/models/<model>/write Update existing records by IDs
POST /mcp/api/v1/models/<model>/unlink Delete records by IDs
POST /mcp/api/v1/models/<model>/call Call arbitrary model method with args/kwargs

XML-RPC Endpoints

/mcp/xmlrpc/2/object execute_kw(db, uid, password, model, method, args, kwargs)

Usage Examples

Quick start with curl and Python

Search Partners (curl)

curl -X POST http://localhost:8069/mcp/api/v1/models/res-partner/search \ -H "Authorization: Bearer YOUR_API_KEY" \ -H "Content-Type: application/json" \ -d '{"domain": [["is_company", "=", true]], "fields": ["name", "email"], "limit": 5}'
Note: Use dashes (res-partner) instead of dots (res.partner) in the URL path for model names.

Create a Record (curl)

curl -X POST http://localhost:8069/mcp/api/v1/models/res-partner/create \ -H "Authorization: Bearer YOUR_API_KEY" \ -H "Content-Type: application/json" \ -d '{"values": {"name": "New Partner", "email": "new@example.com", "is_company": true}}'

XML-RPC (Python)

import xmlrpc.client common = xmlrpc.client.ServerProxy('http://localhost:8069/mcp/xmlrpc/2/common') print(common.version()) uid = common.authenticate('your_db', 'admin', 'admin', {}) models = xmlrpc.client.ServerProxy('http://localhost:8069/mcp/xmlrpc/2/object') partners = models.execute_kw('your_db', uid, 'admin', 'res.partner', 'search_read', [[]], {'fields': ['name', 'email'], 'limit': 5}) print(partners)

VS Code Integration

Use Odoo data directly from VS Code AI chat (Copilot, Claude, etc.)

⚡

How It Works

The module includes a MCP Bridge script (mcp_bridge.py) that translates between the MCP protocol (used by VS Code) and the Odoo REST API. Your AI assistant in VS Code gets 12 tools to interact with Odoo.

You (VS Code Chat) → AI Assistant (Copilot / Claude) ↓ MCP Bridge (mcp_bridge.py) ← stdio protocol ↓ Odoo REST API → /mcp/api/v1/... ↓ Database → Returns JSON data ↓ AI reads data and gives you a human-friendly answer
1

Install Python Dependencies

The bridge requires two Python packages: mcp and httpx.

pip install "mcp[cli]" httpx
2

Create VS Code MCP Config

Create .vscode/mcp.json in your workspace root (or in ~/.vscode/mcp.json for global config):

.vscode/mcp.json
{ "servers": { "odoo": { "command": "python3", "args": [ "/path/to/mcp_server_ai/mcp_bridge.py" ], "env": { "ODOO_URL": "http://localhost:8069", "ODOO_API_KEY": "your-api-key-here", "ODOO_DB": "your-database-name (required for multi-db production)" } } } }
Tip: You can use ODOO_LOGIN + ODOO_PASSWORD instead of ODOO_API_KEY for Basic Auth, but API keys are recommended for production.
3

Reload VS Code

Press Ctrl+Shift+P → type "Reload Window" → select "Developer: Reload Window". The MCP server will auto-start.

4

Start Using in Chat

Open the AI chat panel (Ctrl+Shift+I). Click the tools icon (wrench) in the chat input — you should see "odoo" listed with 12 tools. Then just ask in natural language:

Available MCP Tools in VS Code

ToolWhat It DoesExample Prompt
odoo_health Check server status "Is Odoo running?"
odoo_system_info Get version & DB info "What Odoo version is this?"
odoo_list_models List exposed models "What models can I access?"
odoo_model_fields Get field metadata "Show fields on res.partner"
odoo_search Search with domain filter "Find all company partners"
odoo_browse Paginated search + summary "Browse sale orders, page 2"

Tip: You don't write any code — just ask questions in natural language in the VS Code chat panel. The AI automatically picks the right tool, calls the Odoo API, and shows you the results.

Other AI Client Configuration

Connect Claude Desktop, Claude Code CLI, or Cursor to Odoo

Claude Desktop

Config file: ~/.config/claude/claude_desktop_config.json (Linux) • ~/Library/Application Support/Claude/claude_desktop_config.json (macOS) • %APPDATA%\Claude\claude_desktop_config.json (Windows)

{ "mcpServers": { "odoo": { "command": "python3", "args": ["/path/to/mcp_server_ai/mcp_bridge.py"], "env": { "ODOO_URL": "http://localhost:8069", "ODOO_API_KEY": "your-api-key-here", "ODOO_DB": "your-database-name" } } } }

After saving, restart Claude Desktop completely. You'll see "Odoo MCP Server" in the tools list.

Claude Code (CLI / VS Code Extension)

Run this command in your terminal:

# Step 1: Install dependencies pip install "mcp[cli]" httpx # Step 2: Add MCP server (available in all projects) claude mcp add-json odoo '{ "command": "python3", "args": ["/path/to/mcp_server_ai/mcp_bridge.py"], "env": { "ODOO_URL": "http://localhost:8069", "ODOO_API_KEY": "your-api-key-here", "ODOO_DB": "your-database-name" } }' -s user # Step 3: Restart Claude Code, then verify # Type /mcp in Claude Code — should show: odoo - Connected
Scope options: -s user = available in all your projects (recommended) • -s local = only current project (private) • -s project = shared via .mcp.json (for teams)

To remove or update: claude mcp remove odoo -s user • To list servers: claude mcp list

Cursor IDE

Config file: ~/.cursor/mcp.json

{ "mcpServers": { "odoo": { "command": "python3", "args": ["/path/to/mcp_server_ai/mcp_bridge.py"], "env": { "ODOO_URL": "http://localhost:8069", "ODOO_API_KEY": "your-api-key-here", "ODOO_DB": "your-database-name" } } } }

After saving, restart Cursor. The Odoo tools will appear in the AI assistant's tool list.

Tip: Replace /path/to/mcp_server_ai/mcp_bridge.py with the actual full absolute path to the bridge script in your Odoo installation, e.g. /opt/odoo/addons/mcp_server_ai/mcp_bridge.py
Important: ODOO_DB is required for production servers with multiple databases. The bridge sends it as the X-Odoo-Database header (Odoo 19 native). For single-database setups it can be omitted.

Error Responses

Standard error codes returned by the API

HTTP CodeError CodeMeaning
401 AUTH_INVALID Missing or invalid credentials (no header, wrong password, invalid API key)
403 BLOCKED_MODEL Model is security-blocked (e.g., ir.config_parameter, ir.rule)
403 OPERATION_DENIED Operation not allowed on model (e.g., delete when delete_access=False)
404 MODEL_NOT_FOUND Model is not exposed via MCP (not in Model Access list)
429 RATE_LIMITED Rate limit exceeded — includes retry_after value in seconds
500 INTERNAL_ERROR Server error (check Odoo logs for details)

Security Best Practices

Keep your Odoo instance secure

🔐

Use HTTPS in Production

Always deploy behind a reverse proxy (Nginx/Caddy) with TLS certificates to encrypt API traffic.

🔑

Unique API Keys

Generate a separate API key for each AI integration. Revoke individually if compromised.

🌐

Enable IP Whitelist

In production, restrict access to known IP addresses only. One IP per line in settings.

📋

Minimal Model Exposure

Only expose models that your AI needs. Use field restrictions to hide sensitive columns.

🚫

Disable YOLO Mode

YOLO mode bypasses all permission checks. Never enable it in production environments.

📈

Review Audit Logs

Regularly check audit logs for suspicious activity. Logs auto-cleanup after 90 days (configurable).

Warning: Never commit API keys to version control. Use environment variables or Odoo's system parameters for sensitive configuration.
